# 🏠 Home Rent Prediction — End-to-End MLOps Application

A production-style, end-to-end MLOps project: a Flask web app that predicts
monthly home rent from house details (location, BHK, area, bathrooms,
furnishing, parking), backed by a scikit-learn regression model that is
trained, tracked (MLflow), tested (pytest), containerized (Docker), and
deployed through both **Jenkins** and **GitHub Actions** CI/CD pipelines.

## 3. Local Setup (without Docker)

**Prerequisites:** Python 3.11, pip, Linux/macOS/WSL recommended.

```bash
# 1. Clone the repository
git clone <your-repo-url> home_rent_mlops_app
cd home_rent_mlops_app

# 2. Create & activate a virtual environment
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Generate the sample dataset
python src/generate_data.py

# 5. Validate the dataset (Step 1)
python src/data_validation.py
# -> writes data/validation_report.json

# 6. Train the model (Steps 3-5, with MLflow tracking)
python src/train.py
# -> writes models/model_latest.joblib + models/model_metadata.json
# -> logs runs to ./mlruns (local MLflow file store)

# 7. Run unit tests (Step 7)
pytest -v --cov=src --cov=app tests/

# 8. Start the Flask app
python app.py
# -> visit http://localhost:5000
```

### Inspect MLflow experiments locally

```bash
mlflow ui --backend-store-uri ./mlruns
# -> visit http://localhost:5000  (MLflow's own UI, use a different port if
#    your Flask app is already using 5000, e.g. `mlflow ui --port 5001`)
```

You'll see one experiment (`home_rent_prediction`) with two runs
(`linear_regression`, `random_forest`), each with logged parameters,
metrics (`r2_score`, `mae`, `rmse`), and the model artifact itself.

## 4. Running with Docker

```bash
# Build and run with docker-compose (recommended)
docker-compose up --build

# App is now live at http://localhost:5000
```

Or manually with plain Docker:

```bash
docker build -t home-rent-mlops-app:latest .
docker run -d -p 5000:5000 --name home_rent_app home-rent-mlops-app:latest

# Check health
curl http://localhost:5000/health
```

The Docker image trains the model **during the build**, so the container
is immediately ready to serve predictions on first run — no separate
training step needed at deploy time.

## 6. MLOps Lifecycle Explained

| Step | File(s)                         | What it does |
|------|----------------------------------|---------------|
| 1. Data Ingestion & Validation | `src/data_validation.py` | Loads CSV, checks schema/nulls/duplicates, writes `validation_report.json`, raises on invalid data |
| 2. Preprocessing | `src/preprocessing.py` | One-Hot Encoding (categoricals) + StandardScaler (numerics) inside a single reusable `ColumnTransformer` / `Pipeline` |
| 3. Model Training | `src/train.py` | Trains `LinearRegression` and `RandomForestRegressor`, evaluates both with R² & MAE |
| 4. MLflow Tracking | `src/train.py` | Logs params, metrics, and the fitted pipeline as an artifact for every run, under experiment `home_rent_prediction` |
| 5. Model Registration | `src/train.py` | Persists the winning model with a timestamped version (`model_v<ts>.joblib`), updates `model_latest.joblib` + `model_metadata.json` |
| 6. Flask App | `app.py`, `templates/`, `static/` | Serves the form, validates input, loads the registered model, returns predictions, exposes `/health` |
| 7. Unit Testing | `tests/test_app.py` | Tests health endpoint, prediction logic (valid/invalid inputs), and data validation functions |
| 8. Dockerization | `Dockerfile`, `docker-compose.yml` | Builds a reproducible image that trains the model at build time and serves via `gunicorn` |
| 9. Jenkins CI/CD | `Jenkinsfile` | Automates checkout → install → validate → train → test → build → deploy |
| 10. GitHub Actions | `.github/workflows/ci.yml` | Runs the same pipeline on every push/PR: install → train → test → docker build → smoke test |

### Model selection strategy

Both candidate models are trained on an 80/20 train-test split. The model
with the **highest R² score** is selected; **MAE** is used as a tie-breaker
when R² scores are very close. On the bundled sample dataset, **Random
Forest** typically wins (R² ≈ 0.95 vs ≈ 0.94 for Linear Regression).

### Model versioning strategy

Every training run writes an immutable, timestamped artifact
(`model_v20260714050000.joblib`) — nothing is ever overwritten — plus a
`model_latest.joblib` pointer file that the Flask app always loads, and a
`model_metadata.json` recording which model won, its metrics, and its
MLflow `run_id` for full traceability back to the experiment that produced
it. This gives you the same guarantees as an MLflow Model Registry
(Staging/Production aliases) without requiring a running MLflow server at
inference time.

## 7. CI/CD Pipelines

### Jenkins (`Jenkinsfile`)

Stages: **Checkout → Install Dependencies → Data Validation → Train Model →
Unit Tests → Docker Build → Docker Deploy → Smoke Test**.

To use it:
1. Install the Jenkins Docker + Pipeline plugins on your Ubuntu Jenkins host.
2. Create a new Pipeline job pointing at this repository, using
   "Pipeline script from SCM" with this `Jenkinsfile`.
3. Configure a GitHub webhook (or poll SCM) to trigger builds on push.

### GitHub Actions (`.github/workflows/ci.yml`)

Runs automatically on every push/PR to `main`/`develop`: installs
dependencies, generates/validates data, trains the model, runs pytest,
builds the Docker image, and smoke-tests it — no extra setup required
beyond pushing to GitHub.

## 9. Notes on the Sample Dataset

`data/home_rent_data.csv` is **synthetically generated** (see
`src/generate_data.py`) so the whole project runs out-of-the-box with no
external data dependency. It deliberately includes a handful of null
values and duplicate rows so the data validation stage has something
real to catch — mirroring the kind of messiness you'd see in a real
rental-listings export. Swap in your own real dataset (same 7 columns:
`location, bhk, area_sqft, bathrooms, furnishing, parking, rent`) at any
time — the rest of the pipeline needs no changes.
