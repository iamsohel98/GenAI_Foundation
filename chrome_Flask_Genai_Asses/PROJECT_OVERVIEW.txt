================================================================================
TECHNICAL ARCHITECTURE
================================================================================

Request Flow:
  User Question
    → Flask receives via POST /ask
    → Encode to vector (SentenceTransformer)
    → Search ChromaDB (cosine similarity)
    → Get top 3 chunks + scores
    → Build prompt with context
    → Call Claude API
    → Parse response
    → Return JSON with results
    → Display in web UI

Vector Dimensions: 384 (all-MiniLM-L6-v2)
Similarity Metric: Cosine distance
Distance Range: 0-2 (0=identical, 2=opposite)
Similarity Percentage: (1 - distance) * 100

================================================================================
CHROMADB BENEFITS IN RAG
================================================================================

1. Semantic Search - Finds by meaning, not keywords
2. Fast Retrieval - Indexed O(log n) search, not O(n)
3. Similarity Scoring - Automatic relevance ranking
4. Persistence - Knowledge survives app restarts
5. Scalability - Can handle 1000s of documents
6. Metadata Support - Filter by topic, difficulty, etc.
7. Real-time Updates - Add documents on the fly
8. Reduced Hallucination - LLM grounded in real context

See: HOW_CHROMADB_HELPS_RAG.md for detailed explanation
